# 按失败原因恢复

先读 `apply` 的 `attempts`、`transactions[].reasons`、`errors` 和完整复核，保留首次证据。没有错误就不启动恢复。

v1.4可用 `check-review` 只读检查同一复核。它运行相同放行规则，并定位required_anchor_empty、anchor_literal_mismatch、anchor_outside_unit的单元及字段。诊断不修改文字或判断，也不意味着这些错误都能修格式：锚点选择过宽或省略主体的引用遗漏，与正文真正改变动作、条件或主体，须分别判断。存在后一种情况时保留回退或进行一次正文repair。无实质变化且首次明确pass时，证据引用错误可纳入既有的一次格式补取额度，不另增重试额度。

| 观察到的失败 | 下一步 | 停止条件 |
|---|---|---|
| 提案/补丁哈希过期、坐标或保护内容错误 | 回到当前原文重新准备；不要强行套用旧补丁 | 原件不变，过期候选不交付 |
| 复核JSON不完整、缺维度/claims/全文衔接，或输出截断 | 对**相同原文、候选、补丁ID和hash**补取一次完整复核；小批次或单项进行 | 仍缺证据则回退；不把它解释成正文写坏了 |
| 格式完整，但语义明确fail或unknown | 保留该判断；有明确局部修复办法时最多一次正文repair，否则回退 | 不以改提示或重试评分将fail/unknown刷成pass |
| 事务通过但全文衔接字段缺失 | 补同一候选的全文复核；不要提交“编辑修复” | 衔接仍不确定就回退 |
| 部分事务回退 | 重新通读实际保留的最终组合，提供绑定其hash的coherence_review | 不复用旧组合的全文pass |
| 身份认证/订阅额度不足 | 保存进度，停止该通道；在现有会话内完成可独立工作 | 不换未授权付费通道、不无限重试 |

格式恢复与正文修复是不同事件，分别记录次数。格式补取不能改候选；正文repair只改变首次失败事务的 `new` 和相关理由，仍受原补丁ID、范围、old、依赖与claim范围限制。修复时不要重新调用 `build-bundle` 缩放原范围。

格式缺项也包括维度before/after为空、已声明为discourse_preview却把存留主题填到after或把行文动作填成事实anchor、非preview误填topic_units等可定位的契约错误。补取时同时列出全部已知缺项，避免一个字段一次重试。实际信息遗漏、作用范围变化、收益不足及明确fail/unknown仍是实质问题，不能以“修格式”名义改判。原样分句提供的pass/note同样是审阅判断，不可由宿主补写。

格式补取时保留首次已完整有效的事务判断和全文衔接判断，只补缺失部分。首次某事务已明确fail，不得因为其他字段缺失而用第二次的pass覆盖它。

`check` 的 `unresolved_group_bindings` 表示多组关系超出当前机械识别能力；必须在实际语义复核中逐组检查。`duplicate_deletion_evidence` 只记录字面重复副本的位置，不是自动删除授权，也不证明编辑有收益。

交付时把“原文无需修改”“问题尚未解决”“检查失败后回退”说清楚。`checked_edit` 仅表示通过这次有限检查；没有真人参与就不写成人工审阅。
